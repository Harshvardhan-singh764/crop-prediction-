# Backend Schema & Database Design
## AI-Based Crop Recommendation for Farmers
**Smart India Hackathon 2025 | Problem Statement ID: 25030**

---

## 1. Database Architecture Overview

The system uses a **relational database (PostgreSQL)** with JSONB support for flexible data storage, complemented by **Redis** for caching and **MinIO/S3** for file storage.

### 1.1 Database Technology Stack

| Component | Technology | Purpose |
|-----------|------------|---------|
| **Primary Database** | PostgreSQL 15+ | Relational data, ACID compliance, JSONB support |
| **Vector Extension** | pgvector | Future ML embeddings, similarity search |
| **Cache Layer** | Redis 7+ | Session management, API caching, rate limiting |
| **File Storage** | MinIO / AWS S3 | Model files, user uploads, crop images |
| **ORM** | SQLAlchemy 2.0 / Prisma | Database abstraction, migrations |

## 3. Detailed Table Schemas

### 3.1 Core Tables

#### **users**
Stores all farmer/user information.

```sql
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    phone_number VARCHAR(15) UNIQUE NOT NULL,
    name VARCHAR(100),
    preferred_language VARCHAR(10) DEFAULT 'en',
    location_lat DECIMAL(10, 8),
    location_lng DECIMAL(11, 8),
    state VARCHAR(50),
    district VARCHAR(50),
    village VARCHAR(100),
    pin_code VARCHAR(10),
    farm_size DECIMAL(10, 2), -- in acres
    is_verified BOOLEAN DEFAULT FALSE,
    is_active BOOLEAN DEFAULT TRUE,
    last_active TIMESTAMP,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    device_token TEXT, -- For push notifications
    auth_provider VARCHAR(20) DEFAULT 'phone',
    auth_id VARCHAR(255)
);

-- Indexes
CREATE INDEX idx_users_phone ON users(phone_number);
CREATE INDEX idx_users_location ON users(location_lat, location_lng);
CREATE INDEX idx_users_state_district ON users(state, district);
```

#### **queries**
Tracks all recommendation requests.

```sql
CREATE TABLE queries (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID REFERENCES users(id) ON DELETE CASCADE,
    input_features JSONB NOT NULL, -- {N, P, K, temp, humidity, pH, rainfall}
    location JSONB, -- {lat, lng, state, district}
    crop_name VARCHAR(50),
    confidence FLOAT,
    status VARCHAR(20) DEFAULT 'pending', -- pending, processing, completed, failed
    error_message TEXT,
    response_time_ms INTEGER,
    device_info JSONB,
    ip_address INET,
    is_offline BOOLEAN DEFAULT FALSE,
    synced_at TIMESTAMP,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Indexes
CREATE INDEX idx_queries_user ON queries(user_id);
CREATE INDEX idx_queries_created ON queries(created_at DESC);
CREATE INDEX idx_queries_status ON queries(status);
CREATE INDEX idx_queries_crop ON queries(crop_name);

-- Check constraint for valid input features
ALTER TABLE queries ADD CONSTRAINT valid_input_features CHECK (
    (input_features->>'N')::float BETWEEN 0 AND 100 AND
    (input_features->>'P')::float BETWEEN 0 AND 100 AND
    (input_features->>'K')::float BETWEEN 0 AND 100 AND
    (input_features->>'pH')::float BETWEEN 0 AND 14
);
```

#### **crops**
Master table for all supported crops.

```sql
CREATE TABLE crops (
    id SERIAL PRIMARY KEY,
    name VARCHAR(50) UNIQUE NOT NULL,
    scientific_name VARCHAR(100),
    category VARCHAR(30), -- cereal, pulse, oilseed, fiber, fruit, vegetable
    image_url TEXT,
    icon_emoji VARCHAR(10),
    
    -- Optimal growing conditions
    growing_days INTEGER,
    optimal_temp_min FLOAT,
    optimal_temp_max FLOAT,
    optimal_ph_min FLOAT,
    optimal_ph_max FLOAT,
    optimal_rainfall_min FLOAT, -- mm
    optimal_rainfall_max FLOAT, -- mm
    
    -- Requirements
    soil_preferences JSONB, -- {type: [sandy, clay, loam], texture, drainage}
    water_requirements JSONB, -- {irrigation: high/medium/low, water_stress_tolerance}
    fertilizer_needs JSONB, -- {nitrogen: high/medium/low, phosphorus, potassium}
    
    -- Economic data
    avg_yield_per_acre DECIMAL(10, 2), -- in kg/acre
    market_demand_score INTEGER CHECK (market_demand_score BETWEEN 1 AND 10),
```

#### **recommendation_results**
Stores detailed recommendation results for each query.

```sql
CREATE TABLE recommendation_results (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    query_id UUID UNIQUE REFERENCES queries(id) ON DELETE CASCADE,
    crop_id INTEGER REFERENCES crops(id),
    confidence FLOAT CHECK (confidence BETWEEN 0 AND 1),
    reasoning TEXT,
    
    -- Factors contributing to recommendation
    soil_match_score FLOAT,
    weather_match_score FLOAT,
    market_score FLOAT,
    final_score FLOAT,
    
    -- Contextual data
    weather_factors JSONB, -- {temperature_suitability, rainfall_suitability}
    market_factors JSONB, -- {current_price, demand_trend, seasonal_demand}
    
    generated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_results_query ON recommendation_results(query_id);
CREATE INDEX idx_results_crop ON recommendation_results(crop_id);
CREATE INDEX idx_results_confidence ON recommendation_results(confidence DESC);
```

#### **alternative_crops**
Stores alternative crop recommendations.

```sql
CREATE TABLE alternative_crops (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    result_id UUID REFERENCES recommendation_results(id) ON DELETE CASCADE,
    crop_id INTEGER REFERENCES crops(id),
    confidence FLOAT CHECK (confidence BETWEEN 0 AND 1),
    reason TEXT,
    rank INTEGER,
    
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_alternatives_result ON alternative_crops(result_id);
CREATE INDEX idx_alternatives_rank ON alternative_crops(rank);
```

## 5. Query Examples

### 5.1 Get Full Recommendation with All Data

```sql
WITH user_context AS (
    SELECT 
        u.id as user_id,
        u.location_lat,
        u.location_lng,
        u.state,
        u.district,
        shc.soil_ph,
        shc.nitrogen,
        shc.phosphorus,
        shc.potassium
    FROM users u
    LEFT JOIN soil_health_cards shc ON shc.user_id = u.id AND shc.is_current = true
    WHERE u.id = :user_id
),
weather_context AS (
    SELECT 
        temperature,
        humidity,
        rainfall,
        condition
    FROM weather_data
    WHERE lat = (SELECT location_lat FROM user_context)
    AND lng = (SELECT location_lng FROM user_context)
    AND is_forecast = false
    AND recorded_at >= NOW() - INTERVAL '1 hour'
    ORDER BY recorded_at DESC
    LIMIT 1
),
market_context AS (
    SELECT 
        mp.crop_id,
        AVG(mp.modal_price) as avg_price,
        AVG(mp.demand_score) as avg_demand
    FROM market_prices mp
    WHERE mp.recorded_at >= CURRENT_DATE - INTERVAL '30 days'
    GROUP BY mp.crop_id
)
SELECT 
    q.id as query_id,
    q.input_features,
    r.crop_id,
    c.name as crop_name,
    r.confidence,
    r.reasoning,
    r.weather_factors,
    r.market_factors,
    COALESCE(mc.avg_price, 0) as market_price,
    COALESCE(mc.avg_demand, 5) as market_demand,
    w.temperature,
    w.humidity,
    w.rainfall
FROM queries q
INNER JOIN recommendation_results r ON r.query_id = q.id
INNER JOIN crops c ON c.id = r.crop_id
LEFT JOIN weather_context w ON TRUE
LEFT JOIN market_context mc ON mc.crop_id = r.crop_id
WHERE q.id = :query_id
AND q.user_id = :user_id;
```

### 5.2 Get Top Crops for Location and Season

```sql
SELECT 
    c.id,
    c.name,
    c.optimal_temp_min,
    c.optimal_temp_max,
    cs.season,
    COUNT(q.id) as recommendation_count,
    AVG(r.confidence) as avg_confidence
FROM crops c
INNER JOIN crop_seasonality cs ON cs.crop_id = c.id
LEFT JOIN recommendation_results r ON r.crop_id = c.id
LEFT JOIN queries q ON q.id = r.query_id
WHERE cs.region IN ('all', :region)
AND cs.season = :season
AND c.is_active = true
GROUP BY c.id, c.name, c.optimal_temp_min, c.optimal_temp_max, cs.season
ORDER BY avg_confidence DESC
LIMIT 10;
```
